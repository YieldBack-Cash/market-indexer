# Frontend integration guide

How the Next.js frontend consumes this indexer, and what still needs wiring.

The frontend lives in a **separate repository** (`../frontend` locally). Nothing in this repo
changes it — this document is the contract between the two.

---

## Transport

`lib/indexer/client.ts` holds a single `indexerFetch<T>` over plain `fetch`. The base URL is
`NEXT_PUBLIC_INDEXER_URL`, set to `/api/indexer` in `.env.local` and rewritten by
`next.config.ts` to the real API. The proxy exists because this indexer's CORS only allows the
production frontend origin (`FRONTEND_ORIGIN`), so browser requests must not hit it directly
from localhost.

React Query wraps every call. Key convention is `["indexer", "vaults", address, …]`, with global
defaults in `app/providers.tsx` (`staleTime: 10s`, `refetchInterval: 30s`, `retry: 2`).

---

## Endpoints

| Endpoint | Returns | Notes |
|---|---|---|
| `GET /markets` | listed, unexpired markets | `?includeExpired=true` to include matured |
| `GET /markets/:id/events` | market events, newest first | id is the composite `vault:maturity` |
| `GET /vaults` | every vault, markets nested | markets filtered the same way |
| `GET /vaults/:address` | one vault + its markets | **404** on unknown address |
| `GET /vaults/:address/markets` | one vault's markets | `?includeExpired=true` supported |
| `GET /vaults/:address/rate-history` | `{rate, timestamp}[]` | hourly snapshots |
| `GET /vaults/:address/events` | factory events for the vault | |
| `GET /accounts/:address/balances` | `{marketId, ptBalance, ytBalance}[]` | **includes expired** |
| `GET /status` | `{lastPolled, lastLedger}` | |
| `GET /events` | factory events | `?limit=N`, capped at 500 |

Two behaviours worth internalising:

- **`/markets` is an allowlist.** Only curated markets come back. An empty array on a fresh
  database is correct, not a bug.
- **`/accounts/:address/balances` deliberately includes matured markets**, so unredeemed PT/YT
  stays visible. Don't filter it by `isActive` on the client.

`/admin/*` requires a secret header and must never be called from the browser.

## Wire types

Every `BigInt` column is serialized as a **string** (`maturity`, `currentApy`, `apyMin`,
`apyMax`, `feeApy`). `curationNote` is stripped from all public responses — it is internal
review copy and will never appear.

`IndexerMarket` currently carries more than the frontend type declares — `creator`, `verified`,
`listed`, `curatedAt`, and the four apy columns are all present on the wire:

```ts
export interface IndexerMarket {
  id: string; vault: string; name: string;
  ym: string; pt: string; yt: string; pool: string;
  maturity: string;            // BigInt as string
  isActive: boolean;           // derived server-side: maturity > now
  listed: boolean; verified: boolean;
  creator: string | null; curatedAt: string | null;
  currentApy: string | null; apyMin: string | null;
  apyMax: string | null; feeApy: string | null;
  createdAt: string; updatedAt: string;
}
```

`IndexerVault` is what needs extending — today the frontend declares only
`{ address, createdAt, markets }`:

```ts
export interface IndexerVault {
  address: string; createdAt: string; updatedAt: string;
  markets: IndexerMarket[];

  // Indexed from the vault contract. Best-effort — any may be null.
  underlyingSymbol: string | null;   // "XLM"
  underlyingAsset: string | null;    // asset contract address
  pool: string | null;               // protocol pool the vault lends into

  // Curated. See docs/CURATION.md.
  displayName: string | null;        // "Blend XLM Vault"
  protocolName: string | null;       // "Blend Capital"
  protocolLogoUrl: string | null;    // "/BLND.png" — path into public/
  protocolWebsite: string | null;
  protocolDocsUrl: string | null;
  protocolAuditUrl: string | null;
  description: string | null;
  riskText: string | null;
  curatedAt: string | null;
}
```

Every metadata field is nullable. Keep a fallback for each — a vault can be indexed before
anyone curates it.

## What still needs wiring

Today the market details page reads its vault and protocol copy from `MARKET_CONFIG` in
`lib/config/marketDetails.ts`, a hand-maintained map **keyed by market name**
(`"XLM-2026-11-17"`). That name is generated by this indexer as `{vaultSymbol}-{maturityDate}`,
so every new maturity mints a key someone has to add by hand in a different repo — and when it's
missing, the market silently renders `"Details coming soon."` from `DEFAULT_MARKET_DETAILS`.

The content is vault-level anyway: both existing entries carry identical
`tags: ["Blend Capital", "XLM"]` and the same `riskText`.

### 1. Client and hook

Add to `lib/indexer/client.ts`, beside the existing `getVaults()`:

```ts
export const getVault = (address: string) =>
  indexerFetch<IndexerVault>(`/vaults/${address}`);
```

Add `useVault(address)` to `hooks/useIndexer.ts` following the existing key convention.

### 2. Replace the hardcodes

| File | Today | Becomes |
|---|---|---|
| `hooks/useMarkets.ts:43` | `protocolIcon: "/BLND.png"` for every market | join `useIndexerVaults()` by address, then `vault.protocolLogoUrl ?? "/BLND.png"` |
| `hooks/useMarketDetails.ts:104` | `MARKET_CONFIG[market.name] ?? {}` | compose from the vault record |
| `lib/config/marketDetails.ts` | `MARKET_CONFIG` | **delete**; keep `DEFAULT_MARKET_DETAILS` and `IMPORTANT_NOTES` as fallbacks |
| `MarketDetailsContent.tsx:32` | `"Variable · from the Blend vault"` | interpolate `protocolName` |
| `MarketDetailsContent.tsx:116` | `"USDC on Stellar"` | interpolate `underlyingSymbol` |
| `MarketDetailsContent.tsx:148` | vault address link only | can now add `displayName`, logo, docs/audit links |

### 3. Compose the copy client-side

The indexer serves structured fields, not sentences. Build the strings in
`deriveMarketDetails` — it is already exported separately for unit testing:

```ts
const tags = [vault.protocolName, vault.underlyingSymbol].filter(Boolean);
const description = vault.description ?? DEFAULT_MARKET_DETAILS.description;
const riskText = vault.riskText ?? DEFAULT_MARKET_DETAILS.riskText;
const ytInfo =
  `1 YT ${ytSymbol} gives you all yield generated by the underlying ` +
  `vault until ${monthYear}. YT value decays to zero at maturity.`;
```

### 4. Tests

`tests/marketDetails.test.ts` asserts every field of `DEFAULT_MARKET_DETAILS`.
`tests/useMarketDetails.test.tsx` already mocks `@/lib/indexer/client` and needs `getVault`
added to the mock. Note there is no shared market fixture — each component test defines its own
`makeMarket()` factory, so adding fields to `MarketDisplay` means touching each one.

## Gotchas

**Two different market ids.** The details page finds a market by `market.id`, which is the **PT
contract address** (`hooks/useMarkets.ts:40`), but calls `/markets/:id/events` with the composite
`vault:maturity` (`useMarketDetails.ts:115`). Join vault metadata on **`market.vault`**, not on
either id.

**`MarketDetailsContent.tsx:116` is wrong today.** It hardcodes `"USDC on Stellar"`, but the
deployed `blend_vault` has `asset.symbol: "XLM"`. The PT explainer and `useTradeForm` make the
same USDC assumption. Driving these from `underlyingSymbol` fixes the display; the trade-form
assumption is a separate correctness question.

**`MARKET_CONFIG` may already be dead in production.** Its keys are `"XLM-…"`, but market names
come from `{vaultSymbol}-{maturityDate}` where the symbol lookup used to call `asset()` on the
vault — while the SEP-56 interface these vaults implement declares `query_asset`. When that
failed, the indexer fell back to the vault's own `symbol()`, i.e. `"bVS"`. Check before assuming
the map ever matched:

```bash
curl https://api.yieldback.cash/markets | jq '.[].name'
```

The indexer now tries `query_asset` first and falls back to `asset`, so new markets get the real
symbol. **Existing rows keep the name they were created with** — moving to vault-sourced metadata
removes the dependency on that name entirely, which is the main reason to do it.

**A market can be listed before its vault is curated.** Vault metadata is descriptive and never
gates listing, so every field needs a fallback path.

**`useMarketDetails` silently degrades.** If `NEXT_PUBLIC_FACTORY_CONTRACT_ID` is unset it
returns the hardcoded base without calling the chain or the indexer, and any thrown error falls
back the same way. When live data doesn't appear, check that env var before suspecting the API.
